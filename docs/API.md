# RTChesz API

Базовый адрес в разработке: `http://localhost:3000`. Формат обмена - JSON (`Content-Type: application/json`).
Поля в ответах - `camelCase`. Время - ISO 8601 (UTC).

## Ошибки

Все ошибки имеют один формат, текст `message` на русском и безопасен для показа пользователю:

```json
{ "code": "conflict", "message": "Этот email уже зарегистрирован" }
```

| HTTP | `code`              | Когда                                                                                      |
| ---- | ------------------- | ------------------------------------------------------------------------------------------ |
| 400  | `bad_request`       | не прошла валидация, неверный код, битый JSON                                              |
| 401  | `unauthorized`      | неверный email/пароль, нет или просрочен токен (ответ содержит `WWW-Authenticate: Bearer`) |
| 404  | `not_found`         | нет такого маршрута                                                                        |
| 409  | `conflict`          | email или имя пользователя уже заняты                                                      |
| 429  | `too_many_requests` | превышен лимит; заголовок `Retry-After` - через сколько секунд повторить                   |
| 500  | `internal`          | ошибка сервера (подробности только в логах)                                                |

`Retry-After` разрешён для чтения из браузера (`Access-Control-Expose-Headers`).

## Авторизация

После `register` / `login` возвращается JWT (`token`). Для защищённых маршрутов:
`Authorization: Bearer <token>`. Срок жизни - 7 дней (`JWT_TTL_HOURS`).

## Эндпоинты

### `GET /health`

`200 { "status": "ok", "db": "ok" }`. Если БД недоступна: `503 { "status": "degraded", "db": "down" }`.

### `POST /auth/register`

```json
{
  "username": "alice",
  "email": "alice@example.com",
  "password": "supersecret1"
}
```

- `username`: 3-24 символа, буквы/цифры и `_ - .`; уникально без учёта регистра
- `email`: корректный адрес, хранится в нижнем регистре
- `password`: 8-128 символов

`201`:

```json
{
  "token": "<jwt>",
  "user": {
    "id": "uuid",
    "username": "alice",
    "email": "alice@example.com",
    "createdAt": "2026-10-25T12:00:00Z"
  }
}
```

Ошибки: `400` (валидация), `409` (email / имя заняты), `429`.

### `POST /auth/login`

```json
{ "email": "alice@example.com", "password": "supersecret1" }
```

`200` - тот же ответ, что у `register`. Неверный email и неверный пароль неразличимы:
`401 { "message": "Неверный email или пароль" }`.

### `GET /auth/me`

`200 { "id", "username", "email", "createdAt" }`. Удобно, чтобы проверить токен при загрузке приложения.

### Восстановление пароля (3 шага)

**1. `POST /auth/forgot-password`**

```json
{ "email": "alice@example.com" }
```

`200 { "message": "..." }` - **всегда**, существует email или нет (чтобы нельзя было перебирать аккаунты).
Если аккаунт есть, на почту уходит 6-значный код (действует 10 минут). Новый код гасит предыдущие.
Повторный запрос на тот же email раньше чем через 60 секунд: `429` + `Retry-After`.

**2. `POST /auth/verify-code`**

```json
{ "email": "alice@example.com", "code": "123456" }
```

`200 { "resetToken": "<64 hex>" }` (действует 15 минут, одноразовый).
`400` - код неверный / просрочен / закончились попытки (5 на один код; тогда нужно запросить новый).

**3. `POST /auth/reset-password`**

```json
{ "resetToken": "<из шага 2>", "password": "new-password-42" }
```

`200 { "message": "Пароль изменён" }`. Токен после этого недействителен. `400` - токен неверный или истёк,
или пароль не прошёл валидацию. Войти новым паролем нужно через `POST /auth/login`.

## Лимиты запросов

Считаются по IP клиента, при превышении - `429` + `Retry-After`.

| Действие          | Лимит                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------ |
| `register`        | 10 в час                                                                                   |
| `login`           | 20 в минуту; плюс 10 неудачных входов на один email за 15 минут (успешный вход сбрасывает) |
| `forgot-password` | 10 за 15 минут с IP; 1 в 60 секунд на один email                                           |
| `verify-code`     | 20 за 15 минут                                                                             |
| `reset-password`  | 10 за 15 минут                                                                             |

## CORS

Разрешены источники из `CORS_ORIGINS` (по умолчанию dev-сервер Vite, `http://localhost:5173`),
методы `GET, POST, OPTIONS`, заголовки `Content-Type, Authorization`.
