# RTChesz API

Базовый адрес в разработке: `http://localhost:3000`. Формат обмена - JSON (`Content-Type: application/json`).
Поля в ответах - `camelCase`. Время - ISO 8601 (UTC).

## Ошибки

Все ошибки имеют один формат, текст `message` на русском и безопасен для показа пользователю:

```json
{ "code": "conflict", "message": "Этот email уже зарегистрирован" }
```

| HTTP | `code`              | Когда                                                                                              |
| ---- | ------------------- | -------------------------------------------------------------------------------------------------- |
| 400  | `bad_request`       | не прошла валидация, неверный код, битый JSON                                                      |
| 401  | `unauthorized`      | неверный email/пароль, нет или просрочен токен (ответ содержит `WWW-Authenticate: Bearer`)         |
| 403  | `forbidden`         | действие недоступно: например, ход в чужой партии                                                  |
| 404  | `not_found`         | нет такого маршрута или партии                                                                     |
| 409  | `conflict`          | email или имя заняты; действие не подходит текущему состоянию партии (не ваш ход, партия окончена) |
| 429  | `too_many_requests` | превышен лимит; заголовок `Retry-After` - через сколько секунд повторить                           |
| 500  | `internal`          | ошибка сервера (подробности только в логах)                                                        |
| 503  | `unavailable`       | БД перегружена или недоступна; заголовок `Retry-After: 5`, запрос можно повторить                  |

`Retry-After` и `X-Request-Id` разрешены для чтения из браузера (`Access-Control-Expose-Headers`).

## Request ID

Каждый ответ (и успешный, и с ошибкой) содержит заголовок `X-Request-Id`. Тот же ID стоит в каждой строке
серверного лога этого запроса, поэтому по нему можно найти, что произошло: `docker compose logs api | grep <id>`.
Если прислать свой `X-Request-Id` (до 64 символов: латиница, цифры, `-`, `_`), сервер сохранит его,
иначе сгенерирует UUID. Если пользователь жалуется на ошибку, просите у него этот ID.

## Авторизация

После `register` / `login` возвращается JWT (`token`). Для защищённых маршрутов:
`Authorization: Bearer <token>`. Срок жизни - 7 дней (`JWT_TTL_HOURS`).

Токен можно отозвать раньше срока. Он перестаёт работать (`401`), когда:

- пользователь сменил пароль через восстановление (`reset-password`);
- пользователь вызвал `POST /auth/logout` (выход на **всех** устройствах);
- пользователь удалён.

Токены, выданные до появления этой возможности, продолжают работать до первого из этих событий.
При `401` фронту нужно сбросить сохранённый токен и отправить пользователя на вход.

## Эндпоинты

### `GET /health`

`200 { "status": "ok", "db": "ok" }`. Если БД недоступна: `503 { "status": "degraded", "db": "down" }`.

### `POST /auth/register`

```json
{
  "username": "alice",
  "email": "alice@example.com",
  "password": "supersecret1"
}
```

- `username`: 3-24 символа, буквы/цифры и `_ - .`; уникально без учёта регистра
- `email`: корректный адрес, хранится в нижнем регистре
- `password`: 8-128 символов

`201`:

```json
{
  "token": "<jwt>",
  "user": {
    "id": "uuid",
    "username": "alice",
    "email": "alice@example.com",
    "createdAt": "2026-10-25T12:00:00Z"
  }
}
```

Ошибки: `400` (валидация), `409` (email / имя заняты), `429`.

### `POST /auth/login`

```json
{ "email": "alice@example.com", "password": "supersecret1" }
```

`200` - тот же ответ, что у `register`. Неверный email и неверный пароль неразличимы:
`401 { "message": "Неверный email или пароль" }`.

### `GET /auth/me`

`200 { "id", "username", "email", "createdAt" }`. Удобно, чтобы проверить токен при загрузке приложения.

### `POST /auth/logout`

Нужен заголовок `Authorization: Bearer <token>`. `200 { "message": "Вы вышли на всех устройствах" }`.
Отзывает **все** токены пользователя, а не только текущий. Для обычного «выйти» на одном устройстве
достаточно удалить токен на клиенте. Без токена - `401`.

### Восстановление пароля (3 шага)

**1. `POST /auth/forgot-password`**

```json
{ "email": "alice@example.com" }
```

`200 { "message": "..." }` - **всегда**, существует email или нет (чтобы нельзя было перебирать аккаунты).
Если аккаунт есть, на почту уходит 6-значный код (действует 10 минут). Новый код гасит предыдущие.
Повторный запрос на тот же email раньше чем через 60 секунд: `429` + `Retry-After`.

**2. `POST /auth/verify-code`**

```json
{ "email": "alice@example.com", "code": "123456" }
```

`200 { "resetToken": "<64 hex>" }` (действует 15 минут, одноразовый).
`400` - код неверный / просрочен / закончились попытки (5 на один код; тогда нужно запросить новый).

**3. `POST /auth/reset-password`**

```json
{ "resetToken": "<из шага 2>", "password": "new-password-42" }
```

`200 { "message": "Пароль изменён" }`. Токен после этого недействителен, а все выданные ранее токены входа
отозваны (на всех устройствах нужно войти заново). `400` - токен неверный или истёк,
или пароль не прошёл валидацию. Войти новым паролем нужно через `POST /auth/login`.

## Партии и часы

Все маршруты `/games/*` требуют `Authorization: Bearer <token>`. Партию может читать любой авторизованный
пользователь (наблюдение), действовать в ней - только участники (иначе `403`). Сервер сам реализует
правила шахмат (`ruleset: "standard"`) и сам считает время: клиент ходов не проверяет и часы не ведёт,
а только показывает их по ответам сервера.

Жизненный цикл `status`: `waiting` (вызов ждёт соперника) -> `active` -> `finished` (есть `result`)
или `aborted` (отменена до двух первых ходов, результата нет).

### Модель партии (`GameResponse`)

```json
{
  "id": "uuid",
  "status": "active",
  "white": { "id": "uuid", "username": "alice" },
  "black": { "id": "uuid", "username": "bob" },
  "timeControl": { "initialSecs": 300, "incrementSecs": 3 },
  "ply": 3,
  "result": null,
  "termination": null,
  "createdAt": "2026-11-04T10:00:00Z",
  "ruleset": "standard",
  "moves": ["e2e4", "e7e5", "g1f3"],
  "fen": "rnbqkbnr/pppp1ppp/8/4p3/4P3/5N2/PPPP1PPP/RNBQKB1R b KQkq - 1 2",
  "legalMoves": ["a7a6", "a7a5", "b7b6", "..."],
  "turn": "black",
  "clock": { "whiteMs": 301000, "blackMs": 300000, "running": "black" },
  "drawOfferedBy": null,
  "serverTime": "2026-11-04T10:01:00Z",
  "startedAt": "2026-11-04T10:00:05Z",
  "finishedAt": null
}
```

- `white` / `black` - `null`, пока в вызове нет второго игрока. Ходы - в формате UCI (`e2e4`, `e7e8q`).
- `turn` - `"white"` / `"black"` только у идущей партии, иначе `null`.
- `legalMoves` - все разрешённые ходы стороне, которая ходит, в UCI. Пусто, если партия не идёт (ждёт соперника или окончена). Клиенту не нужно считать правила: подсвечивать и отправлять можно только ходы из этого списка.
- `result` - `"white"`, `"black"` или `"draw"`; `termination` - причина: `checkmate`, `stalemate`,
  `insufficient_material`, `fifty_move_rule`, `threefold_repetition`, `resignation`, `timeout`,
  `draw_agreement`, `aborted`.
- `clock` - остаток времени в миллисекундах **на момент `serverTime`**. `running` - чьи часы тикают
  сейчас (`null` - стоят). Клиент рисует обратный отсчёт локально: `остаток - (сейчас - момент получения ответа)`,
  а при каждом новом ответе сервера подменяет значения серверными.
- `drawOfferedBy` - цвет игрока, предложившего ничью (`null` - предложения нет).

В списках (`lobby`, `mine`) элементы - краткая форма: `id`, `status`, `white`, `black`, `timeControl`,
`ply`, `result`, `termination`, `createdAt`.

### Правила часов

- Время на партию - `initialSecs` каждому, после каждого хода `incrementSecs` добавляется сделавшему ход.
- Часы запускаются, когда оба игрока сделали по первому ходу. Первый ход каждого инкремента не даёт.
  До этого на первый ход есть 60 секунд (`GAME_FIRST_MOVE_TIMEOUT_SECS`); не сходили - партия `aborted`.
- Время вышло - `finished`, `termination: "timeout"`, победа соперника. Это фиксируется сразу при любом
  обращении к партии и фоновой проверкой раз в 2 секунды. Ход после флажка получает `409`, но результат сохраняется.
- Ограничения: `initialSecs` 15 - 10800, `incrementSecs` 0 - 180.

### `POST /games`

Создаёт открытый вызов. Создатель занимает свой цвет, партия ждёт соперника.

```json
{ "timeControl": { "initialSecs": 300, "incrementSecs": 3 }, "color": "random" }
```

`color`: `white`, `black` или `random` (по умолчанию). `incrementSecs` по умолчанию 0.
`201` - `GameResponse` со статусом `waiting`. `400` - неверное время или цвет;
`409` - уже 5 открытых вызовов; `429` - больше 20 вызовов в час.
Невостребованные вызовы удаляются через 15 минут (`GAME_CHALLENGE_TTL_MINUTES`).

### `GET /games/lobby`

`200 { "games": [ ...краткая форма... ] }` - открытые вызовы других игроков, свежие первыми (до 50).

### `GET /games/mine[?status=waiting|active|finished|aborted]`

`200 { "games": [...] }` - партии текущего пользователя (включая его открытые вызовы), свежие первыми (до 50).

### `GET /games/{id}`

`200` - `GameResponse`. Опрашивать можно раз в секунду-две: если время вышло, результат фиксируется
в этом же запросе. `404` - нет такой партии (в том числе неверный формат id).

### `POST /games/{id}/join`

Принять чужой вызов: свободный цвет достаётся вам, партия начинается. `200` - `GameResponse`.
`400` - свой вызов; `409` - к партии уже нельзя присоединиться.

### `POST /games/{id}/moves`

```json
{ "move": "e2e4" }
```

`200` - `GameResponse` после хода (если ход закончил партию - уже с `result` и `termination`).
`400` - запись хода некорректна или ход недопустим; `409` - не ваш ход, партия не идёт или время вышло;
`403` - вы не участник; `429` - больше 20 ходов за 10 секунд.

### `POST /games/{id}/resign`

Сдаться (можно в любой момент идущей партии). `200` - `GameResponse`.

### `POST /games/{id}/abort`

Отменить партию. Свой вызов (`waiting`) удаляется: `200 { "message": "Вызов отменён" }`.
Идущую партию, где ещё нет двух ходов, помечает `aborted` и возвращает `GameResponse`.
Дальше - `409` (можно только сдаться).

### `POST /games/{id}/draw`

Предложить ничью (после двух первых ходов). Если соперник уже предлагал, это согласие: партия
заканчивается вничью (`termination: "draw_agreement"`). Любой ход снимает предложение.
`409` - вы уже предложили / слишком рано; `429` - больше 5 предложений за 10 минут в одной партии.

### `POST /games/{id}/draw/decline`

Отклонить предложение ничьей (или забрать своё). `409` - предложения нет.

## Лимиты запросов

Считаются по IP клиента, при превышении - `429` + `Retry-After`.

| Действие          | Лимит                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------ |
| `register`        | 10 в час                                                                                   |
| `login`           | 20 в минуту; плюс 10 неудачных входов на один email за 15 минут (успешный вход сбрасывает) |
| `forgot-password` | 10 за 15 минут с IP; 1 в 60 секунд на один email                                           |
| `verify-code`     | 20 за 15 минут                                                                             |
| `reset-password`  | 10 за 15 минут                                                                             |
| `POST /games`     | 20 в час на пользователя                                                                   |
| ход в партии      | 20 за 10 секунд на пользователя                                                            |

## CORS

Разрешены источники из `CORS_ORIGINS` (по умолчанию dev-сервер Vite, `http://localhost:5173`),
методы `GET, POST, OPTIONS`, заголовки `Content-Type, Authorization`.
